# Caelestis S.E.A.R.C.H. — Setup & Maintenance

Client-side search for the Caelestis site, powered by Pagefind. Three separate
indexes keep the player / DM / FIA boundaries intact.

The player-facing terminal is branded **S.E.A.R.C.H.** — *Standard Enquiry of
Assets, Records & Communications Hub*. Lives at `/search/`.

---

## THE ONE THING YOU DO ONCE

After this lands and you push it, flip a single setting so the GitHub Action
publishes the site (instead of Pages serving the raw repo):

**Repo → Settings → Pages → Build and deployment → Source → select "GitHub Actions"**

That's it. From then on, every push to `main`:
1. builds the three search indexes fresh from your current HTML
2. deploys the whole site with them included

You never run anything. Push HTML like always; search rebuilds itself.

> First deploy note: the index is generated on GitHub's servers during the
> Action, not committed to the repo. Until the first successful Action run,
> the search pages will say "index not yet available." That's expected — it
> resolves the moment the first Action completes.

## WHAT GOT BUILT

**Four search surfaces:**

| Surface | URL | Index it uses |
|---|---|---|
| Global player search | `/search/` | player |
| Per-section box | on each section index page | player (filtered) |
| DM search | `/prime/search.html` (gated) | DM |
| FIA search | `/restricted/search.html` (gated) | FIA |

**Three indexes** (generated by the Action):
- `/pagefind/` — player-facing pages only
- `/prime/pagefind/` — DM wiki
- `/restricted/pagefind/` — FIA archive

**What's in the player index:** root, crew-logs, crew-manifest, dossiers,
spelljammer-nexus, inventory, handouts, navigation-records.

**What's excluded from it:** prime/, restricted/ (own indexes),
wayfinder-path/, stellar-chart/ (player-specific, JS-hidden — kept out
entirely), scripts/data/styles/, and *-template.html.

## HOW SCOPING WORKS

The security boundary is the index itself: the player index only *contains*
player-facing content, so no search from the player side can surface DM or FIA
material — it's simply not in the file being searched.

The per-section filtering (global search dropdown, per-section boxes) uses a
`data-pagefind-filter="section:X"` attribute on each player page's `<body>`.
The dropdown filters the one player index by that tag. New player pages get
indexed automatically; to make a new page filterable by section, add the same
attribute to its `<body>` (matching its top-level directory).

## ALIAS MAINTENANCE — the one ongoing task

Pagefind matches partial words (Vir → Viren) and word variants (tether →
tethered) automatically, but NOT raw misspellings (Veren ≠ Viren). Since your
world runs on invented names players only ever *hear*, we seed common
misspellings as hidden search aliases on each name's canonical page.

**When a new manglable name enters play**, add its variants to that name's
most authoritative page. Find the hidden alias span (or add one) just after
`<body...>`:

```html
<span class="pf-aliases" aria-hidden="true"
      style="position:absolute;width:1px;height:1px;overflow:hidden;clip:rect(0 0 0 0);white-space:nowrap;">
  Variant1 Variant2 Variant3
</span>
```

The words inside get indexed but never display. A player who types the wrong
spelling still lands on the right page.

**Currently seeded:**
- `navigation-records/viren.html` — Veren, Viran, Virin, Vyren, Verin, Zerathis variants
- `navigation-records/realmspace.html` — H'Catha variants (Hakatha, Hcatha, …)
- `crew-logs/detailed/voyage-detailed-004.html` — Ostekk-6 variants (Ostek, Aztec, …)
- `dossiers/mirt.html` — Vocath variants (Volkath, Volcath, …)

Rule of thumb: when you write a new voyage log, ask "what will they mishear
this as?" and seed those on the name's home page.

## GATED SEARCH PAGES

The DM and FIA search pages check the same `sessionStorage` auth flag their
directories already use, and bounce to the gate if it's absent:
- DM: `caelestis_continuum_auth`
- FIA: `caelestis_restricted_v1`

Same caveat as the rest of those directories: this is client-side gating —
adequate against accidental discovery, not a determined adversary. The index
files under `/prime/pagefind/` and `/restricted/pagefind/` are served like any
other file. This is the same exposure your gated *pages* already have; the
search index doesn't widen it. Truly secret content stays out of the published
site entirely (source doc / Drive).

## IF SOMETHING LOOKS OFF

The Action runs with `--verbose`, so the Actions tab log shows exactly what
each Pagefind pass indexed (page count, word count). If a page isn't showing
up in results, check:
1. Is it in the player glob? (the Action's "Build player index" step)
2. Does its content live in the static HTML, or is it injected by JS at
   runtime? Pagefind reads static HTML — JS-rendered content isn't indexed.
   (Known: spelljammer-nexus and the root landing card render some text from
   data/*.js. The destination pages they link to are static and index fine.)
3. For a section filter miss: does the `<body>` have the right
   `data-pagefind-filter="section:X"`?
